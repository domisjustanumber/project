## Context continuity

After compaction, handoff, or resume, treat recall as incomplete. Before the next
edit, recover the task's purpose, relevant ontology, ownership boundaries,
accepted decisions and existing implementation from the task checkpoint and
targeted project sources. Search the owning code before inventing a missing
definition or interface. Continue authorized work once this context is restored;
compaction does not reopen approval or require a full project audit.

For substantial work, maintain a concise task-specific checkpoint at milestones
and after material user corrections. Preserve rationale, rejected alternatives,
exact checkout and document paths, verification evidence, unresolved questions,
and the next action's recovery reading list. Include its path when summarizing or
handing off. Do not depend on a pre-compaction warning or hook.

Read `~/.codex/skills/context-continuity/SKILL.md` when maintaining this checkpoint
or recovering a substantial task (use `$CODEX_HOME/skills/context-continuity/SKILL.md`
if a custom Codex home is configured). Apply it to explicit handoff documents as
well as automatic compaction; preserve any requested handoff destination.
Resolve gaps through targeted inspection. Ask the user only when a consequential
conflict about intent remains unresolved; pause dependent work, continue safe
independent work, and retain uncertainty explicitly.
